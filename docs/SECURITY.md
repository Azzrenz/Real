## 上报漏洞

请**不要**通过公开 Issue 上报安全问题。

使用 GitHub 的私密上报通道：仓库 **Security → Advisories → Report a vulnerability**。

上报时请附：

- 受影响的版本或 commit
- 复现步骤与所需前置条件
- 影响面判断（能读到什么 / 能改到什么 / 是否需要本地交互）
- 如有：最小复现用例

## 本项目的安全模型

理解以下几点，能帮你判断什么是真问题、什么是有意设计。

### 1. 本地优先，非多租户

Real 设计为**单用户本地运行**。后端默认只监听 `127.0.0.1`，不面向公网。

**把后端暴露到公网属于误用**，其带来的风险不在本项目的防护范围内：本项目**不提供 TLS**，
远程访问时设备 token 与 Cookie 在网络上是明文传输的，仅适用于可信局域网。
若确需经公网访问，请自行在反向代理层加 TLS 与认证。

### 2. 来源分两类：回环免鉴权 / 远程须配对

- **回环来源**（`127.0.0.1` / `::1`，即桌面 Tauri 壳与任何本机进程）**免鉴权**——这与旧行为一致，
  桌面体验零变化。注意：**本机进程因此被完全信任**，这仍是有意取舍（旧的「只绑回环」模型同样信任本机进程）。
- **本机反向代理**（`tailscale serve` 等）会把远程请求转成本机回环发起，据此会绕过上面这条。
  开启 `REAL_TRUST_LOCAL_PROXY=1` 后，**仅当**对端是回环时才读 `X-Forwarded-For`：
  取**最后一个**非回环地址作为真实客户端；非回环对端**绝不读该头**。默认 `0`（关），
  关闭时行为与不启用前一致。该头部按**三态、失败关闭**处理：**无该头**（或为空，本机直连的正常形态）
  ⇒ 判回环；**有该头却取不到任何非回环地址**（全回环 / 全不可解析）⇒ **判远程**，视为「经代理但未拿到
  真实客户端」，必须走鉴权——绝不回退到 peer，否则本机代理若原样透传客户端的伪造头即成免鉴权后门。
  该开关不扩大信任面：本机进程本来就被完全信任，而采信本机写下的头部最多只能**加重**
  本机调用者自己的鉴权负担。
- **非回环来源**必须持有效设备 token：在电脑上生成 6 位配对码（仅本机可调），手机用码换取 token
  （HttpOnly Cookie 或 `Authorization: Bearer`）。token 等价于**对本机 Agent 的完整控制权**，
  一旦泄露，请立即在「设备」列表里踢掉该设备。
- 少数**仅限本机**的能力，远程即便持有效 token 也拒绝：MCP 服务器配置的写/生效/重连，
  以及数据根（`data_dir`）的修改——分别对应「任意命令执行」与「数据根被换 = 数据丢失」。
- 模型服务端点（`base_url`）远程可改，但**只允许改成内置厂商档案（`providers/*.json`）里登记的地址**
  （枚举式白名单）。这样手机能正常跨厂商切模型，而把端点指向攻击者自己的域名既不是"别家官方 host"、
  格式也合法——只靠黑名单判不出来的那类地址——会被白名单挡住。
- 未鉴权的非回环请求一律得到 **404**（不暴露服务存在）。
- **可选静态前端托管**（`REAL_SERVE_WEB`，**默认 0 关**）：开启后，非 `/api/*` 的 GET/HEAD
  从 web 根（`REAL_WEB_DIR`，缺省 `<项目根>/client/dist`）提供前端文件，找不到的路径回落到
  `index.html`（SPA）。**静态资源免 token**（否则手机连界面都拿不到），而 `/api/*` 的鉴权口径
  **完全不变**（`auth_guard::needs_auth` 只覆盖 `/api/` 前缀）；未匹配的 `/api/*` 走 API 的 404、
  绝不被 SPA 回落成页面。路径穿越（`..`、反斜杠、非法百分号编码、跳出根目录）一律 403。
  默认关时**不注册任何回落**，行为与不开启时逐字节一致。

### 3. Agent 有真实的文件与命令权限

这是它的功能，不是缺陷。它会读写项目目录下的文件、执行命令。因此：

- **不要把它指向你不信任的目录。**
- 关键操作存在确认门（confirm gate），但请把它当作**降低误操作概率的机制，而非安全边界**。

### 4. 凭据存放

API Key 存于本地 SQLite（`real.db` 的 `settings` 表）或环境变量。

- `.env` 与 `*.db` 均已被 `.gitignore` 排除。
- **请勿把带有真实 Key 的配置文件提交到任何仓库。**
- 设备 token 在库中**只存 SHA-256 哈希**，明文仅在配对响应里返回一次。

### 5. 已知设计取舍

| 行为 | 说明 |
|---|---|
| 回环来源免鉴权 | 保证桌面零变化；代价是本机进程被完全信任（与旧模型一致） |
| 信任本机代理的 `X-Forwarded-For`（可选开关） | 为适配 `tailscale serve` 这类本机代理；默认关，且只在对端是回环时才读 |
| 远程须配对设备 token | token 等权于完整 Agent 控制权；可按设备撤销 |
| 无 TLS | 仅适用于可信局域网；公网暴露属误用 |
| MCP 写/生效/重连与 `data_dir` 仅本机 | 分别对应任意命令执行与数据根被换，故远程一律拒绝 |
| 远程读 MCP 配置只回请求头**键名** | `headers` 常含 `Authorization` 等密钥，值不随 GET 下发给已配对手机；写入口本就仅本机，抹值不影响保存 |
| 远程不下发数据根绝对路径 | `GET /api/settings` 的 `data_dir`/`data_root_effective` 对非回环来源回 `null`，不泄露磁盘布局 |
| 可选静态前端托管（`REAL_SERVE_WEB`，默认关） | 让手机免安装直接开网页；静态资源免 token，但 `/api/*` 鉴权不变、未匹配 `/api/*` 走 API 404、路径穿越一律 403 |
| `base_url` 远程只能改为档案登记地址（枚举式白名单）| 兼顾「手机可跨厂商切模型」与「API Key 不外泄」；本机不受此限 |
| agent 可执行任意命令 | 核心能力，通过确认门与工作区边界约束 |
| 前端 CSP 允许 `unsafe-inline` 样式 | 样式注入需要，脚本侧未放开 |
