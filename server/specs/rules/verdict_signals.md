判一个异步动作有没有结束，**信号分三级**——用错级别，就会去等一个永远不会来的东西：

| 级别 | 信号 | 用途 |
|---|---|---|
| **硬** | 进程在不在（`tasklist`）、`termination` / 退出码 | ✅ **判「结束没有」的唯一依据**——即刻可知，不依赖被观察对象配合 |
| **可观测** | 端口在听（`wait_port`）、HTTP 返回（`wait_http`） | ✅ 判「服务起没起」——外部可观，不靠它自己打印 |
| **软** | 日志里出现「完成 / 成功 / ready / OK」某句话、产物文件出现、睡固定秒数 | ❌ **绝不能当等待条件**，只能当事后线索 |

**禁令**：不得把「日志里出现某句话」当等待条件——脚本随时可能中途死掉，那句话就不会打印。

**动作序列**：
① 先判「结束没有」→ 查进程，或直接看 `termination` / 退出码；
② 进程不在 → **已结束**，到此为止，不要再等任何一句话；
③ 再判**成败** → 退出码 + 日志尾部（**这时日志才有用：它是证据，不是信号**）；
④ 进程还在、且怀疑卡住 → 看产物有没有在长（末次修改时间与大小），**这一步只用来判「有没有在推进」**。
**进程消失且没有产物** = 启动即崩，去读 stderr——**不要把「再等一会儿」当方案**。

**现成工具**：`python <脚本库>/svc.py proc <名>`（进程列表）、`svc.py port <端口>`（谁占着）、`svc.py exe <exe 路径>`（判在跑的是不是刚编出来的那份：比对文件修改时间与进程启动时间，**启动早于改动 = 跑的是旧二进制**）。
