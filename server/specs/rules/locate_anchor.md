**锚点选择**：错误码 > 符号 > 字面量 > 文件名——**越独特越准**。

**降级路径**（前一档不中才往下走）：子串 → 大小写放开 → 拆词去前缀 → **换证据源**（配置 / 日志 / 测试名 / git 历史）。**全库枚举是最后手段。**

**一锚多查**：一次查多个变体（`grep -rn -E 'a|b' <目录>`——Git Bash 原生，`-n` / `-A/-B/-C` 可用）。

**命中后**：用 `read` 拿准行号 ± 上下文再改；真无锚点，才退回列目录。

**改多文件前先盘点**：一条 `run` 列出各文件现状与差异，**禁止拿 A 文件的锚点去套 B 文件**。

**先查环境地图，再动手搜**（要找的东西，八成早有人告诉过你在哪）：

| 要找 | 先去哪 |
|---|---|
| Real 本体代码（仅开发者场景） | 仓库根目录（server=Rust，client=Tauri）；**发行版里没有源码**，用户机器上不要去找 |
| 话术（prompt）工程（仅开发者场景） | 仓库根下 `server/prompts/`（治理规范 `README.md`，正文在 `workflow/` `tools/`）；发行版已编译进程序 |
| 工作规范（specs）（仅开发者场景） | 仓库根下 `server/specs/rules/`（注册表 `src/agent/specs.rs` 定触发词）；发行版已编译进程序 |
| 常用脚本 | `%APPDATA%\real-agent\scripts\` |
| 用户项目的产物 | **本轮项目根** |
| 记忆 / 日志 | `%APPDATA%\real-agent\projects\<项目>\longterm\`、`tasks\<会话>\` |

**「它在哪」也是诊断，2 轮封顶**：第 3 轮只准换证据源（配置 / 日志 / 编译产物 / `git log` / 调用方反查）或**直接问一句**「它在哪个盘 / 哪个项目里」——**全盘枚举是最贵的一条路**。
