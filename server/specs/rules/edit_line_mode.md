# `modify` 的 `line` 模式：三个真实损坏过文件的坑

> 这是对 `edit_safety.md` 的补充。那份文件受「自修改令牌」保护（改动需人工确认），
> 所以新增的这三条单独落在这里。合并时把本文内容并进 `edit_safety.md` 即可。

## ① 插入会让后续行号全变 —— 最容易犯

一次 `modify` 插进 N 行之后，**你手上的旧行号全部失效**。同一批里按旧行号再发 `line`，
改的是**别的行**。

- **判据**：回执里的 `old` 不是你以为的那一行 → **你已经改错了**，立即停下修复，不要接着改下一处。
- **做法**：插入类改动走 `block` + 唯一上下文锚；同一文件多处插入，**一次一条、每次都按刚读到的行号**。

真实代价：给 `shell.rs` 加一个字段，按旧行号连发两次 `line`，把 `player: None,` 与
`peaks: std::cell::RefCell::new(...)` 两行**整个替掉**——编译才报出来，而且报的是
「缺字段」而不是「你改错了行」，定位比原错误更费时。

## ② `block` 插函数进 `impl` 块会撞 `BRACE_UNBALANCED`

护栏查的是**全文件**括号平衡。插入的片段自带一对本该平衡的括号——但只要 `find` 定位
偏移到片段内部，就会报不平衡。

- **做法**：改用 `line` 替换 `impl` 内的锚点行（例如末尾的 `    }`），一次成功。
- **别做**：连试三次不同 `find`。第一次报 `BRACE_UNBALANCED` 就换模式，不要换措辞重试同一个假设。

## ③ 锚点必须是完整表达式

拿 `B::new(\n            "document.punch.set",` 当锚插入内容，会把后面的参数切断 ——
**一处失手，两个文件同时损坏**（`catalog.rs` 与 `bindings.rs` 各一处，因为两张表是同构的）。

- 锚要含收尾：`.build(),` / `}` / `);` / `]`
- 征兆：插入后 `.build(),` 紧跟 `AgentDomain::Document,` 这种位置参数断裂。

## 一条总闸

**改完立刻看回执里的 `old` / `find`，是不是你预期的内容。**

这一条能拦住上面三个坑里至少两个 —— 因为前两个坑都会在回执里显示「你实际改了什么」，
而我这一轮**两次都是没看回执就接着改**。回执不是日志，是校验结果。

## 与 `write` 的分工

- 只改一段 → `modify`，绝不 `write` 全量重写（会丢你看不见的段落）
- 要改的段落占全文大半 / 转义反复失败 → 才用 `write`

本轮反例：`ui/surface.rs` 改 `KNOWN_GAPS` 时因为条目多、换行多，我用了 `write` 整文件覆写。
那次没出事，但**风险在于我看不到被删掉的行**。条目多 ≠ 该整文件重写。
