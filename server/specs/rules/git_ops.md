**改动前先看状态**：`git status --short` + `git log --oneline -5`。仓库常**多个会话/多人并行改动**，动手前先知道现场。

**提交范围要精确**：用 `git add <具体文件>`，**不用 `git add -A`** —— 那会把别的会话、别人的产物、临时文件一起提交。

**任务没要求就不提交**：很多评测按"工作区 diff"取补丁，提交会让 diff 变空。

**回退单个文件**：`git checkout -- <path>`。**备份 ≠ git 原版** —— 备份可能是"已改过"的快照；判基线要看权威源（版本库 / 发行包 / 上游标签），不要看哪份文件更旧。

**危险操作前置**：`reset --hard`、`push --force`、`clean -fd`、`checkout .` 执行前，先 `git stash` 或打 tag —— 否则不可回滚。

**不看 `git diff` 就别删**：删文件/删代码前用 `git log -- <path>` 确认它的来历。
