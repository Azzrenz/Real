**check 与 build 分工**：`cargo check --all-targets`（3–6 秒级，验类型/借用/语法）是**开发期验证**，改完就跑它；`cargo build` 与 `cargo test` 更重（链接 + 执行），**属交付动作** —— 不要替用户决定何时付这个代价。

**`cargo test` 比 `cargo build` 还重**：它要额外链接测试二进制再逐个跑。别以"顺手验证一下"为由代跑。

**`include_str!` / `include_bytes!` 是编译期嵌入**：改 `.md` 话术、模板、静态资源后，**必须重新编译二进制才生效** —— 只改文件对运行中的进程零影响。交付时要显式标注"此项需重编/重启"。

**Windows 上 `target` 被占用**（`OS error 5`、删不掉 exe、链接失败）：有进程还握着旧二进制。按工作目录定位并结束那个进程，再重编。**不要**批量杀进程，也不要改项目自己的构建脚本绕过。

**编译产物不是源码**：`target/` 不进版本控制，也不该被搜索或读取（会命中一堆无关二进制）。搜代码要显式排除。
