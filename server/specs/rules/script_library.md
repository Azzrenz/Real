**先问「短参数工具能否完成」**。下表任一条件成立 → 用对应工具，**不要写脚本**：

| 条件（成立即用对应工具） | 工具 |
|---|---|
| 要读某文件的指定行区间或全文 | `read` |
| 要在文件里按文本/正则找位置 | `run` + `grep -rn`（走 Git Bash，中文精确；**别用 findstr**） |
| 要精确替换已读到的文本 | `modify` |
| 要创建新文件或整文件覆写 | `write` |
| 要列某目录下的文件 | `run` + `dir /b`（短命令，不是脚本） |

只有**需要编程逻辑**（统计、解析 JSON/DB/日志、批量变换、多步管道）才写脚本。

**脚本库**（数据根 `scripts/`；绝对路径见每轮上下文「常用脚本库」一行；**跨项目、跨会话共享**）：

1. **先查**：`python <脚本库>/list.py` —— 列出全部现成脚本（名字 + 用途 + 用法）；
2. **有就用**：`python <脚本库>/<名>.py <子命令> <参数>` —— 参数只有几十字节，**脚本原文不进上下文、不占你的输出**；
3. **没有再写**：确需新脚本时**写完存进脚本库**（`write` 到 `<脚本库>/<用途名>.py`）——**不要**把通用脚本写进项目目录；下次（乃至别的项目）直接调用。

**脚本约定**（保证可被复用）：只用标准库（不装第三方）；可变输入走 `sys.argv`；只打结论行；
顶部 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`；`--help` 打印用法；
首行 docstring 写用途（`list.py` 自动收录）。

**为什么不写长脚本**：脚本原文计入你的输出，越长越容易被 max_tokens 截断——截断后参数残缺，工具报错、白跑一轮。
