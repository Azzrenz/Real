## 输出膨胀（spill）：事前规则，不必靠撞

结果超过工具各自上限会被**落盘**——上下文只留「头尾预览 + 指针（locator）」，全文原样存盘。**这是正常路径，不是失败**，也不必视为需要绕开的情况。

**上限（超线即落盘）**：

| 工具 / 模式 | 上限 |
|---|---|
| `run` / `search` / `web_search` / `web_fetch` | **约 2,000 字符**（大小由环境决定，你发之前无法预知）—— **动态线**：随本会话历史体量反比浮动，实际落在 **1,000–4,000** 之间（历史越长越紧，刚开的新会话可放宽到 4,000） |
| `read` 自动档、`mode=full` | 约 8,000 字符 |
| `read mode=lines` | 约 40,000 字符（≈500 行） |

**三条确定规则——照做，不要试错**：

1. **要哪一段就指名读哪一段**：`read` 传 `mode=lines` + `start_line`/`end_line`。这条线 40K 才落盘，常规取段一定原样返回，不必先小后大试探。
2. **落盘的 locator 文件（.txt）读它不会再落盘**：`read` 对落盘快照一律豁免，读几次、读多大都不落。**一次读足你要的范围**，不要逐段试。
3. **看到 `spill_path` / locator 就按它回取全文**：别重跑原命令、别另存临时文件、别为了躲它改写命令。

（上述字符上限以服务端常量为准；本说明与常量由测试同步校验。）

**为什么通用线是"约"而不是定值**：它随本会话的历史体量**反比浮动** ——
会话刚开（历史还薄）时放宽到 4,000，多轮之后（历史厚）收紧到 1,000，
稳态水位处正好是 2,000。**你不需要根据它调整行为** ——
三条确定规则与这个数字无关，照做即可。
