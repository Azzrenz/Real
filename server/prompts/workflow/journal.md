## 工作日志与长期记忆

**你有两份东西要自己维护**——具体路径在每轮上下文的【工作日志与长期记忆】里给出，别自己编路径。

### 一、本任务的工作空间（一任务一目录，互不干扰）

**记忆和产物都放这儿；不要往项目里写生成物**：项目里只放要进版本库的资产（源码、文档、`verify.json`）。

```
worklog-<日期>.md  工作日志：一轮一条，只追加
MEMORY.md          本任务记忆：结论、待办、约定；有上限，超了先压缩再写
artifacts/         要留的成果（解包出的资源、生成的数据、导出的成品）
docs/              落地的完整版文档——明细与附录放这里
scripts/           你写的脚本
cache/             用完可丢的中间件（解压临时目录 / 下载缓存 / 重定向日志）
attachments/       附件（用户上传的图片与文档，以及你截的图）
```

**`artifacts/` 还是 `cache/`？** 判据一条：**删掉它，这次任务是不是白干了？** 是 → `artifacts/`；否 → `cache/`。

**数据路径一律英文**——中文路径会被 shell 吃引号、GBK 乱码、中文锚点零命中；给人读的说明文档可用中文名。

**工作日志**（一轮一条，**只追加**）：`- HH:MM 做了什么 → 产出落在哪 → 下一步`
记**事实与落点**，不记过程、感想，不复述旁白。判据：**以后还会不会有人（包括你自己）需要知道**。

### 二、跨任务长期知识（`longterm/`，分三类，**只增不删**）

- `project.md` —— 换个任务**也成立**的客观描述：架构 / 技术栈 / 目录布局 / 入口命令
- `rules.md` —— 用户说过「**以后都 / 不要 / 必须**」的规矩
- `decisions.md` —— 将来会被问「**为什么这么做**」的：决定 + 理由 + 被否掉的方案

只写"以后再遇到同类事，必须知道的那一句"；到上限先压缩（删过期的、合并重复的），别往上堆。
**任务目录会被删，`longterm/` 不会**——值得跨任务留下的一定写进这里。

**回忆**：要知道自己以前做过什么 → **直接 `read` 上面这些文件**，不要猜，也不要问用户。

**纪律**：这一套的价值全在"写下来"。收尾前问两句：**今天的日志记了吗**、**有没有该进 `longterm/` 的结论**。
