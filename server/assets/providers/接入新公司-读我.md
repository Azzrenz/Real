# 怎么接入一家新的模型公司（不用改代码）

这个目录就是"模型公司注册表"。**一家公司一个 JSON 文件**，放进来、重启 Real，设置面板里就能选。

---

## 三步

### 1. 复制下面的模板，存成 `providers/<厂商id>.json`

`<厂商id>` 用小写字母，它就是凭据槽的前缀（见第 3 步）。

```json
{
  "id": "moonshot",
  "name": "月之暗面",
  "base_url": "https://api.moonshot.cn/v1",
  "protocol": "chat_completions",
  "vision": false,
  "hosts": ["api.moonshot.cn"],
  "cheap_model": null,
  "provides_web_search": false,
  "models": [
    {
      "id": "kimi-k2",
      "label": "Kimi K2",
      "max_output_tokens": 262144
    }
  ]
}
```

### 2. 重启 Real（双击 `build-run.bat`）

启动日志里会出现：

```
已写入厂商档案 ... providers/moonshot.json
```

### 3. 在设置面板给这家公司填一次 API Key

填完就存进了 `moonshot_api_key` 这个槽位，以后可以一键互切。

---

## 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 厂商标识。凭据槽名由它派生：`<id>_api_key` / `<id>_base_url` |
| `name` | 否 | 界面上显示的厂商名 |
| `base_url` | 是 | 官方端点，**不带** `/chat/completions` 这类路径后缀 |
| `protocol` | 否 | `chat_completions`（默认，OpenAI 兼容的厂商都是这个）或 `responses`（DeepSeek 自有协议） |
| `vision` | 否 | 这家模型能不能看图。`true` 才会把图片发给它，填错会 400 |
| `hosts` | 否 | 官方主机名片段，用于拦截"端点填成别家"的错配。自建代理留空 |
| `cheap_model` | 否 | 可用于标题之类的短输出任务的小模型型号 |
| `provides_web_search` | 否 | 这家的 Key 是否供 web_search 工具使用（一般不用管） |
| `models` | 是 | 型号列表 |

每个型号：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | **发给上游的 API 参数名**（`model` 字段），必须写官方文档里的那个名字 |
| `label` | 否 | 界面上显示的版本名（如 `DeepSeek V4.1 Flash`）。填了才能看出是哪版 |
| `max_output_tokens` | 是 | 该型号的最大输出 token 数，超了会被自动压到这个值 |

---

## 两个容易踩的坑

**① `id` 和 `label` 是两回事，都要填。**

- `id` 是**接口口径**——发给厂商的 `model` 参数，必须和官方文档一字不差。写错立刻 400。
- `label` 是**版本口径**——给人看的。不填的话界面就显示 API 名（`deepseek-flash`），
  你看不出花的钱买的是哪个版本。

**② 厂商的怪癖（思考参数、特殊字段）不要写进代码。**

目前只有智谱 GLM 有这类怪癖（它的思考开关关不掉，需要恒发 `thinking` 字段）。
这类差异将来会以档案字段的形式表达——**新接入的公司不用管，默认就是通用的 OpenAI 兼容发法**。

---

## 已经内置的两家

`deepseek.json` 和 `glm.json` 是自动生成的，可以直接打开照抄。

> 老版本的 `models.json`（所有厂商挤在一个文件里）会在下次启动时**自动拆分**成本目录下的独立文件，
> 拆分完就不再读取了。原文件不会删，可以留着做备份。
